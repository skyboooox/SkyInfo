# 架构

Flutter 负责界面与配置，Kotlin 负责设备能力、采集、历史、后台及通信。

## 模块

| 模块 | 职责 |
| --- | --- |
| `app/lib/ui/` | 四页、组件、选择器、配置草稿与实体详情 |
| `app/lib/domain/` | 字段/实体模型、网格、时间与绘图算法 |
| `app/lib/data/` | 配置、共享缓存、预览需求租约、原生桥接 |
| `app/lib/l10n/` | 语言加载与生成默认值 |
| `RuntimeCoordinator` | 需求合并、调度、样本与发布 |
| `NetworkAdb / ShellVehicleBridge` | 本机授权、app_process 与会话 |
| `VehicleSession / Subscription / ReadOnlyVehicle` | 身份、SDK 读取、订阅、解码与有效性 |
| `VehicleControls / *ControlPlans` | 固定参数执行、互斥与反馈 |
| `LocalHistory / DerivedReadings / SampleTimes` | SQLite、派生值与时间口径 |
| `ConnectionClient / HaSession / HaDiscovery / HaControlEntities` | MQTT/HA 传输、发现和远程会话 |
| `HaEntitySource / HaEntityModel` | HA 目录、服务能力、状态/属性与目标执行 |
| `OverlayWindow / RuntimeService / BootReceiver` | 悬浮条、前台服务、开机恢复 |
| `tools/` | 构建、生成、资源与设计检查 |

四页共享 Shell；模型、编辑器和通用控件按职责拆分。静态计划与语言镜像由工具生成，维护源见[工具说明](../tools/README.md)。

## 数据流

仪表盘、悬浮条、上传、控制反馈及可见预览声明需求；原生层取并集、展开派生依赖，共享一次初读、订阅和缓存。预览使用独立租约，关闭只释放自身需求。

车辆样本保留 raw、解释版本、来源、质量及时间，统一解码后供界面、历史与上报使用。控制实体只订阅可靠反馈字段，推测实体不批量请求未经确认的读取。订阅与降级策略见[车辆适配](车辆数据适配.md)。

HA 状态适配独立来源命名空间，复用一个 WebSocket 会话。绑定采用连接 UUID、entity_id 与 state/属性键；来源接入和控制规则见[HA 接入](HA实体接入.md)。

只有已配置的仪表盘字段进入本地历史；上报按语义变化合并。来源、单位和会话边界贯穿缓存、历史及绘图，规则见[组件与历史](信息组件与历史.md)。

## 控制与配置

元数据定义界面能力，执行器校验权限、接口、固定参数与反馈；车辆和 HA 使用各自执行链。配置草稿、预览和已保存状态分开，保存失败恢复，关闭不撤销已发送命令。

远程命令与在线会话绑定，无断线执行队列；回执独立重试。协议见[HA 控制](HA控制.md)和[MQTT](MQTT控制.md)。

## 资源

通用 UI/UX 使用固定 Fluorite 子模块，平台映射在 [DESIGN](../DESIGN.md)。中文源为 `app/assets/i18n/zh_CN.json`，Dart/Kotlin 镜像生成；字段、实体、图标 ID 与显示文案分离。语言扩展需检查占位参数及长文本布局。
