# 信息组件与历史展示

本页只维护组件、尺寸、预设与历史语义；通用UI/UX遵循[Fluorite Design](design/fluorite-design/DESIGN.md)，车机差异见[DESIGN](../DESIGN.md)。产品要求见[需求说明](需求说明.md)。最新历史要求为所有连接模式统一使用本地记录；APP0.4.8已统一使用本地记录，验证边界见[开发状态](开发状态.md)。Figma设计中的读数与曲线仍为样例。

## 添加入口与默认组件

“添加组件”统一为先选车辆数据或HA实体，再选兼容样式，最后配置并预览；单数值推荐数值2×2。预设预填数据和样式后进入同一配置器，多选数据与控制使用连续混合列表。操作流程唯一维护于[组件添加与数据选择](组件添加与数据选择.md)，HA来源语义见[HA实体接入](HA实体接入.md)。默认结构为**标题、数值、单位**，默认不添加图标、时间、说明、刻度纹理或其他装饰。

无单位的文本/状态不放占位单位；物理单位未知的数值显示原值。时间显示为互斥选项，异常或过期保留必要的质量标记。只读状态字段仍展示为文本；只有已绑定可控实体且能力满足时，才在控制组件中提供功能区。字段默认选择、单位依据与连接上报规则仍独立。

## 添加组件页的真实数据预览

2026-10-10新增要求针对“10 · 添加组件”的样式和预设缩略预览，不仅是选择字段后的配置预览。预览使用实际小组件渲染与真实数据，展示各样式的特点；以下为选定的预览条目组合，不自动加入用户仪表盘。

| 预览形式 | 典型条目 | 单位 / 内容 |
| --- | --- | --- |
| 默认数值、迷你数值 | 电池电流 · GB；动力电池计算功率 | 已换算A；电压×GB电流÷1000 kW，正放负充 |
| 双值对比 | 电池最高温度、最低温度 | 已内置换算的°C |
| 实体列表 / 热管理预设 | 压缩机功耗、PTC功耗、发动机水泵转速 | W、W、rpm |
| 实体概览 / 电机预设 | 前后电机温度、前后IPM温度 | °C；保留各自来源 |
| 范围条 / 仪表 | 低压电压 | V；沿用明确的显示范围，不冒充厂商安全阈值 |
| 趋势 | 动力电池计算功率或低压电压 | 真实本地历史与当前值 |
| 历史对比 | 电池最高温度、最低温度 | 同时间轴的真实本地°C历史 |
| 状态、文本 / 枚举、状态时间线 | 双区分控、出风组合等有可靠读回的实体 | 已确认状态 / 枚举；时间线仅用已有状态历史 |
| 数据可用性 | 上述代表字段 | 实际有效 / 不可用状态 |
| 控制实体 | 前除霜、空调循环、前排设定温度 | 真实读回；预览只展示，不执行动作 |

APP复用共享缓存和订阅，仅为可见预览声明临时数据需求，关闭页面释放需求；不额外轮询，不开启上报或为浏览预览自动建立历史记录。无有效数据时显示“—”或真实不可用状态，历史不足时显示已有片段或空状态，不用编造的固定值或曲线补齐。用户选择字段后的配置预览继续立即切换到所选真实数据。

Figma使用可追溯的真实采样快照和归档采样历史片段，采样来源、时间与工况记录在交付文档中，页面不增加无意义说明。仅有原始值的记录按当前已确认规则解释一次，不扩大单位确认或控制验收范围；无对应证据时保留空状态。APP已使用真实共享数据，Figma已同步归档采样快照；来源见本轮QA（内部记录，未随公共源码发布），归档采样不是APP本地回调记录。

## 实体与设备控制组件

2026-10-10要求覆盖原独立控制面板方案；以下为新设计，APP实现与验收状态见[开发状态](开发状态.md#entity-control-pending)。参考HA的[Tile](https://www.home-assistant.io/dashboards/tile/)、[Entities](https://www.home-assistant.io/dashboards/entities/)与[卡片功能](https://www.home-assistant.io/dashboards/features/)，在保留SkyInfo固定网格、主题和字体的基础上使用实体概览、能力功能区与详情。

车辆读数、车辆控制和HA实体使用统一选择器，不再单设“实体与设备”入口。连续分类列表逐项选择 → 按能力选择组件 → 配置预览 → 保存到仪表盘。单选实体可用实体卡，多选可用混合列表或设备组合卡；添加设备必须再次选定要展示的实体。选择器只显示名称、类型、状态和X复选框，不执行控制。

| 组件 / 功能 | 使用条件 | 交互 | 尺寸 |
| --- | --- | --- | --- |
| 实体卡 | 单个传感器或控制实体 | 名称/状态打开详情；功能区单独操作 | 2×1、2×2，默认2×2 |
| 开关 | 已确认双态写入及可靠状态反馈 | 显式切换；发送期间禁用，实际状态等待读回 | 实体卡内或列表行内 |
| 选项 | 已确认离散枚举 | 当前选项、下拉选项列表；只列允许值 | 实体卡内或列表行内 |
| 动作按钮 | 瞬时动作、无可靠双态反馈或单一固定参数 | 显式点击；点动按住执行、松开/失焦停止 | 实体卡内或列表行内 |
| 数值控制 | 已确认完整范围、步长、单位、反馈 | 加减/输入；提交校验，不能用显示单位换算写参数 | 实体卡内；复杂输入用2×2 |
| 混合实体列表 | 用户选定的多项传感器与控制 | 连续行，各行独立状态和功能，不提供全组开关 | 2×2、2×4、4×2 |
| 设备组合卡 | 用户选定的同设备实体 | 设备标题下连续实体行，不自动加设备全部功能 | 2×2、2×4、4×2 |

已有12种读数样式继续保留。只读传感器不会因组件外观改变而变成控制；已确认17–33°C范围的前排设定温度可设计数值功能，仅确认25°C的主驾温度独立动作仍是“设为25°C”按钮，不能扩大成任意温度输入。无可靠读回的空气净化按独立动作呈现，不猜测当前开关状态。实体功能支持下方/行内位置，空间不足时扩大尺寸；1×1不承载复杂控制。

图标可选并可关闭，示例为用户已选图标；新建默认不添加。时间显示沿用不显示/更新时间/变动时间互斥规则，只显示相对年龄。编辑与预览不操作车辆；正常浏览中实体操作保留权限、接口兼容性、已确认参数、推测开关与执行互斥检查。不可用不显示为关闭，发送不显示为成功，错误与待验证在实体详情中保留必要提示。

## 组件图标

12种样式均可选择组件图标，默认关闭，仍保留默认的标题、数值、单位结构。图标设置与组件标题、单位、时间单选互相独立；选择图标后可开启显示，也可替换或清除为“无”。不因字段有推荐图标而自动为新组件添加图标。

双值、实体列表、实体概览、状态列表与历史对比另提供逐项图标选择，每项可分别开启、替换或关闭；没有图标的条目不保留空图标位。组件图标位于标题行，逐项图标与该项名称同行；同一字段的质量点仍单独表示质量。小组件、控制实体与悬浮窗共用图标库，按图形用途分类，以连续列表浏览，可按中文图形名称或英文图形ID搜索；未知数据保留通用回退并允许用户替换。

2026-10-10设计图标库扩充为90个图形：60个Tabler线性SVG、30个项目原创SVG；原有49个稳定ID保留。图标按图形名称和用途分类，独立于车辆数据分类，完整推荐映射覆盖91条读数、173项车辆控制和5项APP操作。APP0.5.0已接入全部90个图标及图形分类，原49个资源ID保持。前后部件、各轮位及相似读取通道可以共用图形，但始终保留各自名称、数据绑定与时间。图标映射不改变单位、分类或有效性，也不把功耗候选变成制冷/制热结论。完整来源、授权与逐条映射见[图标资源清单](../design-assets/icons/README.md)。

源图使用24×24网格与2 px线宽，以主题前景色适配深浅色；显示尺寸依组件层级调整，不统一固定为24 px，具体尺寸、间距与对齐见[图标比例规范](../DESIGN.md#八当前figma落地参数)。开启图标后保留固定跨度和读数优先级，必要时重排标题/名称，不能遮挡质量或时间。当前Figma交付可编辑向量、图标属性与选择器；APP已实现搜索、动态选取、保存和持久化，Figma仍为静态设计。

## 组件时间显示

所有展示样式共用“时间显示”单选：**不显示（默认）、上次更新时间、上次变动时间**。不能同时选择后两项；新组件仍默认只有标题、数值、单位。组件配置中的标题、单位与可选图标保持独立，时间不再使用两个可并选的复选框，也不由全局开关强制覆盖。

| 选项 | 时间含义 | 同值有效更新 |
| --- | --- | --- |
| 不显示 | 不显示时间辅助行 | 不改变默认展示结构 |
| 上次更新时间 | 当前字段最近一次被采集层接受的有效样本时间 | 刷新 |
| 上次变动时间 | 当前字段的有效数值、文本、枚举或状态最后一次实际改变的时间 | 不刷新 |

时间辅助行采用相对时间，借鉴[Home Assistant实体卡片](https://www.home-assistant.io/dashboards/entities/#options-for-entities)的呈现方式，按用户要求使用数字与秒、分钟、小时、天，不显示固定的时分秒。0.4.14仅显示“12秒前”“3分钟前”，去掉“更新／变动”前缀；时间未知显示“—”。选项仍决定采用更新时间还是变动时间，每个组件只能选择一种。普通数值不附加质量说明；可用性组件和诊断页继续呈现真实质量状态，无效读数显示“—”，不显示旧值为有效当前值。

| 距有效时间的时长 | 显示规则 | 示例 |
| --- | --- | --- |
| 小于60秒 | 完整秒数，向下取整；不到1秒显示0秒前 | 12秒前 |
| 60秒至不足1小时 | 完整分钟数，向下取整 | 3分钟前 |
| 1小时至不足24小时 | 完整小时数，向下取整 | 2小时前 |
| 24小时及以上 | 完整天数，向下取整；持续用天，不自动切换为月/年 | 1天前 |

不把时钟偏差或异常未来时间显示成负数或虚假的刚更新；不可信时间显示“—”，沿用时间有效性检查。相对年龄随当前时间推进，但不会改写上次更新时间或上次变动时间；失效/断链时保留最后有效时间继续计算年龄，并同时保留质量标记。曲线时间轴、历史区段和记录时间维持各自原有时间格式，不改成相对年龄。

变动比较使用字段的有效值与已确认解释口径，在显示舍入、精度格式化或自定义单位标签之前进行；刷新界面、重开页面、修改显示格式、历史查询、上传成功、连接重试与质量标记变化不能伪造数值/状态变动。按2026-10-09后续要求，首次收到有效值建立APP观察起点，初始化变动计时；相同值后续更新只刷新更新时间。该起点不等于ECU内部物理变化时刻。新来源首次有效值重新建立观察起点，断链/失败保留最后有效时间。未收到有效值仍显示“—”；只有变化回调的来源也不能将其时间冒充周期采样的新鲜度。

有可信源时间戳时沿用并保留来源；没有时，上次更新时间采用APP接受该有效样本的接收时间，上次变动时间采用实际观测到有效值改变的接收时间。没有观察到中间变化时不能推断其发生时刻。采集层需校验乱序、重复和过期回调；时间未知显示“—”，失效/断链保留最后有效时间并同时显示质量状态。会话重建或字段来源、解释口径变化后重新建立比较基准，不能把旧来源与新来源拼成一次值变动。

单值、状态和文本组件显示一条时间；双值、实体列表、概览、状态列表与历史对比按各字段分别显示同一种所选时间，不能用某一项的最新时间代表整组。历史类组件的时间辅助行描述当前字段，不替代曲线时间轴、本地记录时间或历史区段起止时间。所有尺寸保持固定跨度，时间空间不足时重排内容或提示扩大组件，不截断重要读数。

时间元数据复用订阅与共享最新状态缓存，不增加车辆轮询、定时网络请求或历史查询。相对时间只在组件可见时共用一个界面调度器，按下一次显示文本变化的秒/分/小时/天边界重绘；进入后台或组件不可见时停止，恢复可见时重新计算，不为每个字段独立创建常驻计时器，也不额外唤醒车辆或增加上报。最新值、上次更新时间和已知变动时间可在当前会话内存中维护；这不是累积历史。本地历史复用相同订阅，但历史记录与当前相对时间分别维护；不从未知时间补造过去的记录。

## 固定网格尺寸

尺寸表示列×行。1×1是迷你组件，正常默认2×2；用户选择其他尺寸时按对应形状排版，而非任意拉伸内容。APP布局编辑须按格吸附，不适用的尺寸禁用；普通浏览不显示编辑操作。按最新要求，编辑模式的组件只保留一个铅笔；点击进入编辑窗口选择适用的固定跨度或删除组件，取消不保存更改。移除左右箭头、直接删除和右下尺寸按钮，位置通过长按组件拖动并按格吸附。下表是当前设计规格与推荐适用范围，Figma已经提供固定尺寸变体，但原型不执行拖动吸附或动态尺寸切换。

| 1×2 | 竖条、上下排列的双值 | 182×380 px |

参考内容区1568 px宽，使用8列、182 px基础格、16 px间距；宽高公式为基础格×跨度＋间距×(跨度−1)。屏幕变化时统一调整基础格和列数，保留整数跨度、阅读字号与必要滚动；不能为塞进一屏压缩文字。超出容量的列表允许滚动，不能把不同字段拼成同一条。长文本换行或滚动，迷你数值空间不足时使用明确的数值精度或提示扩大尺寸，不截断重要位数。

## 合并展示的约定

实体列表与概览可以并列不同量纲，但每项保留自己的单位、来源和有效性；单体最高/最低、前/后电机等不被合成一个采集字段。双值对比不自动计算差值；派生计算另行校验输入有效性、单位与采样时间差。

历史对比共用纵轴时只接受同单位、同测量/换算口径的数值。单位不同的字段分开显示；来源、单位或解释版本发生变化时分段，不能把不同编码接成一条连续曲线。名称未知的枚举保留原值或未知，不能统一将0显示为关闭。范围条和仪表的10–16 V是用户可编辑的显示范围示例，不是车辆安全阈值或厂商标定；不能确认上下界的字段先使用普通数值展示。

## 主页历史

按2026-10-09最新要求，历史统一读取本地车辆数据记录，**不受HA连接状态影响**，也不随HA/高级MQTT的选择切换来源。0.4.8已完成迁移，验证见[DATA-002](开发状态.md#pending-ui-fixes)。

图表建议默认查看最近30分钟，可选5、15、30分钟或2小时；查看窗口与记录保留期限分别设置。主页选定字段共享本地记录，不需要选择上传、创建HA实体或等待服务器历史。没有本地记录时显示空状态；只有车辆采集断链才产生采集缺口，网络断开本身不停止本地记录。切换连接方式不清空记录、不拼接HA历史，也不自动上传历史或删除HA记录。

### 折线与极值背景

数值趋势、历史对比和历史详情共用一种呈现：**实线连接本地已记录的实际样本，低对比背景带是同一字段、同一时间桶内的最低至最高值**。每个有样本的时间桶单独绘制矩形范围，上沿为最高值、下沿为最低值，与实线共用时间轴和纵轴；不跨空桶插值极值背景。不是实线下方到零轴的面积填充，也不是置信区间。“中间”表示实线位于极值带内，不要求数值是最高/最低的算术中点。

0.4.13按用户反馈取消主线的像素桶首末点抽取：在当时本地12000条限制内（0.8.0已移除此限制），主线保留当前查询窗口的全部有效实际样本及时间。1秒一次、1秒多次的已记录数据不会因组件变窄或查看30分钟而被绘图降成约10秒一个点。同桶里的瞬间峰谷也保留在主线中；时间桶只用于计算和绘制独立的最高/最低背景，不能先跳过样本再估计极值。查看某个桶仍可读取末实际样本代表值及两项极值的真实时间。纵轴自动范围包含背景极值。

数值连续更新时按实际样本时间线性连成折线，覆盖0.4.12统一使用阶梯线的处理。长时间没有新样本时保持上一已知状态，到真实更新时跳变；当前实现按同一段有效记录的正时间间隔中位数×3识别连续区间，阈值限制在5至30秒，此阈值为实现默认值，不是车辆实际采集周期。长间隔、窗口前状态边界及查询末状态保持不生成新数据库样本。页面刷新周期与曲线点间隔分别判断：5秒合并一次查询不代表只留每5秒一个样本。


多字段对比为每条字段各算一条极值带，不把电池最高/最低温度等两个车辆字段合并为同一条背景；这些字段自身的时间内极值与车辆上报的空间最高/最低是不同含义。单样本或最高等于最低时背景自然收合，不人为加宽制造波动。明确不可用记录、暂停记录、字段移除、失效、断链或来源/单位/解释口径变化时，实线和背景一起分段；同一有效来源的稀疏订阅样本跨空桶保持上一已知状态；空桶不等于采集断链，不补造桶内样本或极值。来源只返回代表点而缺少桶内原始样本或可信极值时，仅画实线。

绘图与背景聚合不跳过车辆订阅、不改变上报频率，也不额外轮询或唤醒。极值来自本地已取得记录，不能承诺还原车辆订阅阶段未收到的峰谷。现有本地记录保存实际样本，容量滚动淘汰仍可能缩短实际覆盖时长；保留绘图点不恢复已被容量限制淘汰或采集侧未收到的记录。状态时间线仍使用离散区段，不套用数值极值带。图表时间轴固定在本次本地查询快照，避免缓存数据随页面重绘漂移。有效状态或质量变化触发最多每5秒一次的合并本机历史查询，相同数值仅更新时间不触发；原分钟级窗口刷新保留，离页取消延迟查询。这些查询只读取本机SQLite，不增加车辆轮询或上传。

### Home Assistant模式

HA负责用户选择的数据上报与授权控制，APP历史仍使用本地记录。HA连接、认证、实体映射或服务器Recorder状态不控制本地记录与图表；主页选择和上报白名单继续独立，不为查看历史自动上传字段。历史时间轴为本地接收/记录时间，不冒充ECU生成时间；字段源时间戳存在时单独保留。

### 本地历史记录

该方案适用于HA和高级自定义MQTT全部连接模式。主页字段记录复用共享订阅；同一字段共享一份，移除最后一个主页消费者后停止新增，旧样本滚动淘汰。仅用于悬浮窗或上报的字段不自动进入本机历史。当前默认记录最近30分钟，SQLite容量200MB，无固定条数限制，跨启动保留默认关闭；0.4.8的8MiB/12000条为历史版本限制，已被新方案覆盖；资源实测见开发状态。本地记录不能再被HA连接方式禁止。

记录收到值、原值、单位/解释版本、来源、质量和源时间戳存在性，复用车辆订阅与缓存。高频按实际更新记录，保留真实时间及质量变化；时间桶仅用于曲线范围背景，不能减少持久化采样密度；低频跟随真实更新，曲线按像素宽度降采样，隐藏组件不持续重画。断链、休眠、无效、过期和来源改变保留断点。滚动淘汰时，每个字段保留一条窗口前的最近状态作为边界依据，同样计入200MB容量，不设条数限制。查询保留其真实接收时间，绘图边界点只用于裁切，不写回数据库、不重置更新/变动时间。仅当前记录会话仍启用且末状态有效时，才允许末状态保持至查询时间；旧会话、暂停或失效数据不自动延长。状态保持表示最后已知值，不代表车辆在每个时刻发送了新样本，也不保证未收到的物理变化不存在。容量不足滚动淘汰，界面显示实际覆盖时间，不承诺固定覆盖时长。清空只删除本机历史，不修改车辆或HA。

200MB历史采用文件型SQLite。跨启动保留开启时使用持久数据库，关闭时使用会话缓存数据库并在新会话清理；开关切换保留本会话已有记录，不将“不保留”实现为大容量内存数据库。
