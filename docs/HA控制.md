# Home Assistant连接与控制

当前源码使用原生控制实体，与传感器共同归属SkyInfo设备；此前179个事件脚本保留兼容，不自动删除。旧部署与实车记录见历史说明（内部记录，未随公共源码发布）。0.5.0已在用户10安装并完成真实HA注册及代表无线充电的软件双向验收，见实机报告（内部记录，未随公共源码发布）和[开发状态](开发状态.md)。开发期不要求旧数据兼容；现用事件脚本是业务通道，不是必须删除的存储迁移。

## 原生设备实体

设备标识与原有传感器一致：`skyinfo_<deviceId>`。发现目录来自`entities.json`，固定计划来自已存在的车辆执行器。HA类型按可靠能力选择：

| 类型 | 使用条件 |
| --- | --- |
| switch | 已确认双态反馈和对应开启/关闭参数 |
| select | 有已确认离散状态与多个允许选项 |
| number | 前排设定温度17–33°C、风量1–7；只允许整数 |
| button | 单参数动作、无可靠目标读回或推测动作；每个已允许参数一个按钮 |

传感器保留JSON数字/文本类型、有效单位、device_class及统计定义。REST state本身是文本不代表发布类型错误。无效数值不可用，不能变零；控制反馈不使用请求值乐观更新。

启用“HA远程控制”后，APP以HA WebSocket `mqtt/subscribe`订阅本次随机会话Topic，通过HA MQTT发布服务提交发现配置和实际状态。需要HA已配置MQTT集成且令牌具有该订阅权限；订阅失败保持实体不可操作，并可从诊断查看`ha_entity_subscription`。APP不用保存额外Broker密码。

采用[HA设备级发现](https://www.home-assistant.io/integrations/mqtt/#device-discovery-payload)，将516个控制组件（单动作参数分别为按钮）合并为一条发现消息，避免逐实体发出516次HTTP配置请求；反馈仍逐项按变化发布，推测项不再因独立开关禁用。此数量是HA组件，不是已验收车辆功能数量。发现配置保留，控制状态发布非保留。控制Topic每次重连更换，车辆命令QoS0、非保留，拒绝保留消息；旧会话命令无订阅，不离线积压补放。未知状态、65535、无效质量、双区温度不一致时相关有状态实体不可用。单动作按钮“可发送”只说明执行器入口有效，不证明物理动作已完成；推测按钮与其他已归档控制共用入口和执行校验，不再提供APP推测开关。未验收的事实标签保留。

状态变化才发布，保持原始编码、来源及验证级别，避免仅更新时间变化导致重复请求。主动停止时尽力发布离线。进程被强杀或HTTP不可达时无法保证即时发布离线；无可靠反馈不得把HA遗留显示作为实时车辆状态，重新连接重新同步。

## 参数与保护

本地、HA和高级MQTT共用固定执行器：不接收任意SDK字段/写入数组；车辆写入检查实际权限、有效基线及SDK方法/适配协议，不按user 10、UID2000或完整固件版本字符串阻断。按用户要求不设置APP挡位门槛，实际SDK返回与参数规则保持。已测与推测数量是目录分类，不等于全部物理效果已验收。

## 兼容事件脚本

原有`tools/ha_control.py`生成173项车辆、4项APP独立脚本及一个通用入口，共178个。脚本平台通过设备同名标签筛选，不能把旧脚本描述成原生设备控制实体。原生实体发现和旧脚本可以同时存在，不自动删除用户配置。

兼容HA事件仍校验target、整数value、白名单、command_id、过去30秒至未来2秒时效；时间取HA握手HTTP Date加单调时钟，最近256个命令持久去重。车辆动作不自动重试；回执发送可有限重试，停止或切换目标清空旧队列。

## 回执与验收

| 状态 | 含义 |
| --- | --- |
| confirmed | 配置保存或可靠软件读回等于目标；不证明物理效果 |
| accepted_unconfirmed / partial_unconfirmed / timeout_unconfirmed | 已发送但结果未确认，不重复执行 |
| rejected / unsupported_state / unsupported_environment | 接口拒绝、基线无效或环境不匹配 |
| stop_unconfirmed / error / bridge_unavailable | 停止未确认、错误或桥接不可用 |

最后回执传感器不是全部实体的实时状态。原有HA实车证据、失败记录、恢复操作和物理效果限制仍保留于接口调查（内部记录，未随公共源码发布）及历史说明（内部记录，未随公共源码发布）。本版设备发现与一个代表实体的双向软件链已经实服验收；HA516个组件均归属同一SkyInfo设备、465个推测组件默认禁用。捕获的13个选中字段含12个数值及1个无效null，没有数字作为JSON字符串上报。GB电流旧无单位统计已单项清理并按A重建。其余动作、冷启动与网络掉线重连未逐项验收；不能把本机回归、目录数量或confirmed读回当作物理效果通过。

## APP操作HA现有实体（新增设计）

本文前述发现和远控描述HA操作SkyInfo车辆实体，不等于SkyInfo已经能读取/操作HA中其他实体。本轮新增反向接入：APP从HA读取目录、状态与属性，用户在仪表盘添加实体后才提供匹配功能；悬浮条只读。接入与车辆上报、车辆远控独立，HA来源不重复上报。能力、状态反馈和离线规则只在[HA实体接入](HA实体接入.md)维护，APP已实现，当前验收见开发状态；现有无线充电远控证据不能扩大为全部HA来源能力的物理验收。


## 2026-10-13取消推测开关

用户明确取消APP、HA/MQTT的推测控制开关逻辑；已有控制统一直接使用归档执行能力，默认发现不再因inferred而禁用，availability仍依赖桥接及可靠状态。保留验证等级、173项固定动作/参数、即时接口兼容性、用户/UID/固件、有效基线及反馈校验。移除app_inferred_controls，未知或过期的该旧动作不写配置或车辆。已有HA实体若仍被注册表禁用，其注册表状态须独立核对，不能仅以发现载荷判断实体已经可操作；本轮不自动执行全部候选车辆动作。


## MQTT集成恢复

启用旧集成禁用实体时，HA会重载MQTT；控制状态非保留，APP原有发布缓存不能阻止恢复后的状态重发。沿用HA WebSocket订阅可配置Birth主题（默认`homeassistant/status`），收到配置的在线载荷（默认`online`）仅使控制状态发布缓存失效并重发当前真实状态，不派发控制命令、不把桥接或离线状态强制改为可用。恢复事件合并，失败仅有界重试，正常静态时不定期全量刷173项状态。HA启动事件也触发同一恢复路径。恢复主题及在线载荷可在连接高级配置调整；空主题表示不订阅Birth，HA启动事件及手动重新连接仍可同步。默认主题已有0.7.6真实重载验收，自定义/空主题的本轮覆盖见QA，不混称全部实服已验收。依据[HA官方Birth说明](https://www.home-assistant.io/integrations/mqtt/#birth-and-last-will-messages)，实现和真实恢复验收见本轮QA。
