# 构建与发布

在仓库根目录工作。需要 Git（含 submodule）、Python 3、Docker 和用于临时 MQTT 证书的 OpenSSL。镜像固定 Flutter 3.44.0、Android SDK 36、NDK 28.2.13676358 和 JDK 17；首次构建会下载公开依赖，版本锁与镜像摘要随仓库维护。

```sh
git submodule update --init --recursive
python3 tools/check_project.py
./tools/docker.sh flutter analyze
./tools/docker.sh flutter test
./tools/test-mqtt.sh
./tools/docker.sh flutter build apk --debug --target-platform android-arm64
```

`test-mqtt.sh` 在本机临时启动 Mosquitto 并清理证书与容器，完整 Android 回归同时覆盖 TLS/TCP，不访问个人 Broker、HA 或车辆。仅执行原生离线测试可运行：

```sh
./tools/docker.sh sh -c 'cd android && ./gradlew :app:testDebugUnitTest --no-daemon'
```

生成资源随源码维护，普通构建无需重新生成。

## 签名

开发者可使用 debug 构建。正式 release 使用自己的密钥：

```sh
./tools/signing.sh
./tools/docker.sh flutter build apk --release --target-platform android-arm64
```

`signing.sh` 只在没有配置时创建本机签名。`app/android/key.properties` 和 `app/android/signing/` 已忽略，禁止提交、上传日志或用于 PR CI。正式分发需沿用维护者的发布证书；其他签名不能覆盖安装现有正式包。

工程缺少本机签名时 release 会使用 debug 签名，便于个人源码验证；该产物不得作为正式 release。发布前须核对签名证书、版本与提交。

## 首次公开与版本发布

1. 运行公开内容与回归检查，核对许可和验证范围。
2. 干净克隆初始化子模块，验证构建。
3. 维护者人工确认后创建公开仓库、推送已审阅提交，启用私有漏洞报告。
4. 版本发布另行核对 changelog、签名、SHA-256 和实机未测项，再上传 APK。

CI 只检查源码和匿名测试，不自动发布、安装、连接车辆或使用正式签名。第三方 LGPL 依赖的来源与重新构建说明见[许可清单](../THIRD_PARTY_NOTICES.md)。
