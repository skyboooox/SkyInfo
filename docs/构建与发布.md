# 构建与发布

在仓库根目录工作。需要 Git（含 submodule）、Python 3、Docker 和用于临时 MQTT 证书的 OpenSSL。镜像固定 Flutter 3.44.0、Android SDK 36、NDK 28.2.13676358，Java/Kotlin 编译目标为 17；首次构建会下载公开依赖，版本锁与镜像摘要随仓库维护。

## 发行渠道

使用 alpha/beta/stable 三个 Flavor，默认 alpha，与 debug/profile/release 编译模式独立。alpha 用于本地开发和实机测试，beta 用于公开测试，stable 用于正式发布。三渠道共用包名 `app.skyinfo.vehicle`、配置和设备标识，不能同时安装；相同签名、符合 Android 版本要求时可覆盖安装。应用名分别为 SkyInfo Alpha、SkyInfo Beta、SkyInfo，版本来自安装包，不通过版本字符串或用户配置推断渠道。

| 功能 | alpha / beta | stable |
| --- | --- | --- |
| 测试版提示、提示内“版本与更新” | 显示实际渠道版本 | 隐藏并回收空间 |
| 车辆适配检查、逐字段原值日志 | 包含，从设置→实验室手动触发 | 不打包实现、不注册调用 |
| 关于中的版本、GitHub 入口 | 保留 | 保留 |
| 诊断、实体映射、连接与权限恢复 | 保留 | 保留 |
| 车辆/HA 控制及待验证标记 | 保留 | 保留 |

渠道由统一构建常量控制，不写入用户配置；Flutter 与 Kotlin 使用同一 Flavor。alpha 与 beta 共享测试工具实现和界面样式；CI 检查三渠道的界面、原生调用和 release 构建，测试工具不随 stable debug 构建开放。

## 版本与升级

版本名由 `app/pubspec.yaml` 的基础版本与 Android Flavor 后缀组成；alpha 序号与 Beta 后缀在 `app/android/app/build.gradle.kts` 维护。当前 Beta 在基础版本后追加 `b`，例如 `0.1.1b`，渠道仍由 beta Flavor 决定。

| 用途 | 版本示例 | 命名规则 |
| --- | --- | --- |
| 本地测试 | `0.1.1-alpha.16` | 本地测试迭代递增 alpha 序号 |
| 公开测试 | `0.1.1b` | 基础版本追加 `b`，GitHub Release 标记 Pre-release |
| 正式发布 | `0.1.1` | 使用基础版本 |

发布前核对完整版本名、GitHub 标签和 Release，确认发行标识未被占用。已发布的同名版本与附件不覆盖重写。

`pubspec.yaml` 的 `+N` 是 Android 构建号，与版本后缀独立，每份安装或分发的新 APK 跨渠道单调递增。相同签名、构建号不低于已安装版本时可覆盖安装；从 alpha 转 beta 仍使用更高构建号。更换签名或降级时需卸载，卸载会清除配置、历史及本机 ADB 密钥。测试渠道不保证配置和历史格式的跨版本兼容。

## 检查与构建

```sh
git submodule update --init --recursive
python3 tools/check_public.py
python3 tools/check_project.py
./tools/docker.sh flutter analyze
./tools/docker.sh flutter test --flavor alpha
./tools/docker.sh flutter test --flavor beta
./tools/docker.sh flutter test --flavor stable
./tools/test-mqtt.sh
./tools/docker.sh flutter build apk --flavor alpha --debug --target-platform android-arm64
```

`test-mqtt.sh` 在本机临时启动 Mosquitto 并清理证书与容器，完整 Android 回归同时覆盖 TLS/TCP，不访问个人 Broker、HA 或车辆。仅执行原生离线测试可运行：

```sh
./tools/docker.sh sh -c 'flutter build apk --config-only --flavor alpha --debug && cd android && ./gradlew :app:testAlphaDebugUnitTest :app:testBetaDebugUnitTest :app:testStableDebugUnitTest --no-daemon'
```

本地测试使用 `./tools/release-build.sh`（默认 alpha）；公开测试使用 `./tools/release-build.sh beta`；正式渠道使用 `./tools/release-build.sh stable`。分发构建先清理项目生成缓存，再编译当前源码；依赖缓存继续复用。Release 在 Gradle 中限定为 ARM64，CI 校验 ABI 及 Flutter 运行库；Debug 保留开发调试架构。APK 位于 `app/build/app/outputs/flutter-apk/app-<渠道>-<模式>.apk`；分发脚本将产物另存为 `.local/builds/app-<渠道>-release.apk`，避免下次清理覆盖另一渠道的产物。

生成资源随源码维护，普通构建无需重新生成。

### Alpha性能诊断

Alpha提供默认关闭的内存采样窗口，通过已运行的采集服务启动与读取；beta/stable拒绝这些命令。以下命令由已获授权的本机ADB会话执行，`perf-start`时长为1—180秒，默认120秒；启动和停止异步排队，使用`perf-status`核对实际状态。重复启动不替换正在运行的窗口。

```sh
adb shell dumpsys activity service app.skyinfo.vehicle/.RuntimeService perf-start 120
adb shell dumpsys activity service app.skyinfo.vehicle/.RuntimeService perf-status
adb shell dumpsys activity service app.skyinfo.vehicle/.RuntimeService perf-stop
```

采样只保留最近一窗的计数和耗时，自动结束；不写配置、数据库或逐样本日志。服务dump读取缓存，不等待Flutter。提前停止、停止采集或服务退出会取消诊断超时任务。Flutter监听存在时异步注册FrameTiming，超时、停止或控制器退出时移除监听，并回传一次摘要；未收到摘要显示`flutter: null`，不能解释为零开销。Flutter未响应期间原生诊断仍在期限处停止计数。

计数包括回调接收样本、含派生值的接收处理数、字段数、事件携带字段量、真实读数通知、历史查询点数、批次行数和提交次数。历史载荷复用已有JSON字符串长度，单位为UTF-16代码单元；缓冲字节为现有估算，不是实际磁盘Writes。耗时使用单调时钟，表示经过时间，包含同步监听或等待，不能当作CPU时间；关闭时不注册帧回调或定时任务。

FrameTiming仅统计实际收到的回调帧，提供build/raster耗时总量、最大值和互斥的≤4/8/16/32ms、>32ms分桶；回调可能批量送达，因此窗口边缘含投递延迟，不计算卡顿率。原生转换耗时与Flutter处理耗时不包含对方阶段；消息编码量没有为诊断再次完整序列化。诊断本身的时钟读取、计数同步、帧回调和结束摘要会产生少量开销，CPU/I/O对照需使用一致的诊断状态与完整稳态窗口。

开始时只读缓存SQLite的实际journal/synchronous/page_size/wal_autocheckpoint/cache_size/cache_spill及运行开关、需求数量；不执行flush、checkpoint、适配审计或车辆控制，不包含读数、地址或凭据。服务结束时的既有正常提交行为不变。

## 签名

开发者可使用 debug 构建。分发 APK 使用维护者的发布密钥：

```sh
./tools/signing.sh
./tools/release-build.sh stable
```

`signing.sh` 只在没有配置时创建本机签名。`app/android/key.properties` 和 `app/android/signing/` 已忽略，禁止提交、上传日志或用于 PR CI。正式分发需沿用维护者的发布证书；其他签名不能覆盖安装现有正式包。

工程缺少本机签名时 release 会使用 debug 签名，便于个人源码验证；该产物不得作为正式 release。发布前须核对签名证书、版本与提交。

## 发布检查

1. 运行公开内容与回归检查，核对许可和验证范围。
2. 干净克隆初始化子模块，验证构建。
3. 维护者人工确认后推送已审阅提交和标签；仓库使用公开可见性并启用私有漏洞报告。
4. 版本发布核对 changelog、签名、SHA-256 和实机未测项。仅 beta 标记 GitHub Pre-release；alpha 不创建公开 Release、标签或分发附件。公开发行时上传 APK、对应应用源码、SPAKE2（含 C 子模块）源码与构建配置、SHA256SUMS。

CI 只检查源码和匿名测试，不自动发布、安装、连接车辆或使用正式签名。第三方 LGPL 依赖的来源与重新构建说明见[许可清单](../THIRD_PARTY_NOTICES.md)。
