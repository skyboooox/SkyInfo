# 构建与发布

在仓库根目录工作。需要 Git（含 submodule）、Python 3、Docker 和用于临时 MQTT 证书的 OpenSSL。镜像固定 Flutter 3.44.0、Android SDK 36、NDK 28.2.13676358，Java/Kotlin 编译目标为 17；首次构建会下载公开依赖，版本锁与镜像摘要随仓库维护。

## 发行渠道

使用 beta/stable 两个 Flavor，默认 beta；与 debug/profile/release 编译模式独立。两个渠道共用包名 `app.skyinfo.vehicle`、配置和设备标识，不能同时安装；相同签名、符合 Android 版本要求时可覆盖安装。beta 名称为 SkyInfo Beta，版本名附加 `-beta.1`；stable 名称为 SkyInfo。版本来自安装包，不通过版本字符串或保存的配置推断渠道。

| 功能 | beta | stable |
| --- | --- | --- |
| 测试版提示、提示内“版本与更新” | 显示 | 隐藏并回收空间 |
| 车辆适配检查、逐字段原值日志 | 包含，手动触发 | 不打包实现、不注册调用 |
| 关于中的版本、GitHub 入口 | 保留 | 保留 |
| 诊断、实体映射、连接与权限恢复 | 保留 | 保留 |
| 车辆/HA 控制及待验证标记 | 保留 | 保留 |

渠道由统一构建常量控制，不写入用户配置；Flutter 与 Kotlin 使用同一 Flavor。CI 检查两渠道的界面、原生调用和 release 构建；测试工具不随 stable debug 构建开放。

## 版本与升级

| 项目 | 首版值 |
| --- | --- |
| 测试版 | `0.1.0-beta.1` |
| Git 标签 | `v0.1.0-beta.1` |
| 源码版本 | `app/pubspec.yaml` 中的 `0.1.0+1` |
| Android 构建号 | `1` |
| stable 版本名 | `0.1.0` |

beta 序号由 Android Flavor 后缀维护。每份分发 APK 的构建号跨渠道单调递增；同包名、同签名且构建号不低于已安装版本时可覆盖安装。更换签名或降级时需卸载，卸载会清除配置、历史及本机 ADB 密钥。测试渠道不保证配置和历史格式的跨版本兼容。

## 检查与构建

```sh
git submodule update --init --recursive
python3 tools/check_project.py
./tools/docker.sh flutter analyze
./tools/docker.sh flutter test --flavor beta
./tools/docker.sh flutter test --flavor stable
./tools/test-mqtt.sh
./tools/docker.sh flutter build apk --flavor beta --debug --target-platform android-arm64
```

`test-mqtt.sh` 在本机临时启动 Mosquitto 并清理证书与容器，完整 Android 回归同时覆盖 TLS/TCP，不访问个人 Broker、HA 或车辆。仅执行原生离线测试可运行：

```sh
./tools/docker.sh sh -c 'cd android && ./gradlew :app:testBetaDebugUnitTest :app:testStableDebugUnitTest --no-daemon'
```

测试分发使用 `./tools/docker.sh flutter build apk --flavor beta --release --target-platform android-arm64`；正式渠道使用 `--flavor stable`。Release 在 Gradle 中限定为 ARM64，CI 校验 ABI 及 Flutter 运行库；Debug 保留开发调试架构。APK 位于 `app/build/app/outputs/flutter-apk/app-<渠道>-<模式>.apk`。

生成资源随源码维护，普通构建无需重新生成。

## 签名

开发者可使用 debug 构建。分发 APK 使用维护者的发布密钥：

```sh
./tools/signing.sh
./tools/docker.sh flutter build apk --flavor stable --release --target-platform android-arm64
```

`signing.sh` 只在没有配置时创建本机签名。`app/android/key.properties` 和 `app/android/signing/` 已忽略，禁止提交、上传日志或用于 PR CI。正式分发需沿用维护者的发布证书；其他签名不能覆盖安装现有正式包。

工程缺少本机签名时 release 会使用 debug 签名，便于个人源码验证；该产物不得作为正式 release。发布前须核对签名证书、版本与提交。

## 发布检查

1. 运行公开内容与回归检查，核对许可和验证范围。
2. 干净克隆初始化子模块，验证构建。
3. 维护者人工确认后推送已审阅提交和标签；仓库使用公开可见性并启用私有漏洞报告。
4. 版本发布核对 changelog、签名、SHA-256 和实机未测项。测试渠道标记 GitHub Pre-release；上传 APK、对应应用源码、SPAKE2（含 C 子模块）源码与构建配置、SHA256SUMS。

CI 只检查源码和匿名测试，不自动发布、安装、连接车辆或使用正式签名。第三方 LGPL 依赖的来源与重新构建说明见[许可清单](../THIRD_PARTY_NOTICES.md)。
